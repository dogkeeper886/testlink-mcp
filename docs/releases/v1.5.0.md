# TestLink MCP Server Release Notes
## Version 1.5.0 — Credential redaction and a current protocol revision

### Overview

Two changes matter to anyone running this server: it **no longer hands your TestLink API keys to the client**, and it speaks a current MCP protocol revision. Everything else in this release is internal — test tooling and documentation — and changes nothing about how you use it.

**No breaking changes.** All 27 tools keep their names, arguments, and behaviour.

---

### 🔒 Security: `api_key` is no longer returned

`list_projects` and `list_test_plans` previously returned each row's TestLink **API key in cleartext**, because the server passed TestLink's XML-RPC response through verbatim. Any MCP client calling those tools received a credential it had no use for — and in an MCP setup that payload lands in an LLM's context, where it may be logged or retained beyond this process.

Both tools now strip the field. Everything else in the response is unchanged.

**Scope is complete, not sampled.** TestLink stores an `api_key` column on exactly two tables — `testprojects` and `testplans` — confirmed against the schema rather than by probing. Both affected tools are fixed; there is no third.

This was present since the project's first commit. If you have shared logs, transcripts, or LLM context captured from earlier versions, treat any project or plan API keys in them as exposed and rotate them.

### 🔌 MCP SDK `^1.30.0`

The server and its test runner had drifted onto **different SDK versions**, negotiating different protocol revisions — a bug waiting to surface as "works in the test suite, fails in a real client". Both are now on `^1.30.0`.

Client compatibility **widens** rather than narrows:

| | Before | After |
|---|---|---|
| Highest protocol | `2025-06-18` | `2025-11-25` |
| Negotiates back to | `2024-11-05` | `2024-10-07` |

**On the 2026-07-28 revision:** the MCP spec has since moved to a stateless core, served by SDK v2. That migration is deliberately deferred — it would rewrite all 27 tool declarations and the test runner's client. This server is stdio-only, so most of that revision's changes are not its surface, and the v1 line remains supported. See STORY-013 for the full reasoning.

> **Note for image users:** SDK 1.30.0 pulls new transitive dependencies (`hono`, `jose`, and others) into the production image. They are unused by this stdio-only server but do increase the image's dependency footprint.

### 🧪 Test tooling (internal)

The `qw-*` commands referenced machinery that did not exist. Now ported and working:

- `npm --prefix cicd/tests run drift` — flags a test whose story has moved
- `npm --prefix cicd/tests run audit-bind` — checks each doc against the executable it claims to describe
- `npm --prefix cicd/tests run port-yaml` — scaffolds a doc from an existing YAML

All **19 integration tests** now have a bound test doc under `docs/tests/`, grouped by story, recording *why* each test exists.

### 🧹 Removed

- `test.js` — an early connectivity script with no assertions that always exited 0. It was never referenced and never shipped in the Docker image.

---

### Upgrading

```bash
docker pull dogkeeper886/testlink-mcp:1.5.0
```

No configuration changes. `TESTLINK_URL` and `TESTLINK_API_KEY` work exactly as before.

### Known issues

- Node names longer than 100 characters fail with a cryptic `Unknown XML-RPC tag 'PRE'` rather than a clear validation error ([#111](https://github.com/dogkeeper886/testlink-mcp/issues/111)).
- `list_test_suites` on an empty project raises `[7008] ... is empty` instead of returning an empty list ([#111](https://github.com/dogkeeper886/testlink-mcp/issues/111)).
